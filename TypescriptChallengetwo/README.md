Title
Advanced Throttling: Token Bucket, Concurrent Limits, Throttle Backend, and Throttle Signals

TokenBucketThrottle must implement a token-bucket rate-limiting algorithm: tokens refill at a steady rate up to a maximum capacity, and each request consumes one token; it must subclass SimpleRateThrottle and accept the same rate-string format ("capacity/period" where period is s/sec/m/min/h/hour/d/day, or None to disable) plus scope-based THROTTLE_RATES lookup; token state (the fractional remaining token count and the last refill timestamp) must be stored via a ThrottleBackend per client identity, keyed by scope and client ident; tokens must refill at exactly capacity/period_seconds tokens per second, capped at capacity; wait() must return the seconds until the next whole token becomes available, computed as (1 - remaining_tokens) / refill_rate where refill_rate is capacity / period_seconds; UserTokenBucketThrottle and AnonTokenBucketThrottle convenience subclasses must mirror UserRateThrottle and AnonRateThrottle cache-key behavior respectively (user PK for authenticated, IP for anonymous; AnonTokenBucketThrottle must return None for authenticated requests).
ConcurrentRateThrottle must accept a max_concurrent integer parameter (defaulting to 1) and limit simultaneous in-flight requests per client identity; it must expose a get_ident(request) method consistent with SimpleRateThrottle's get_ident; it must expose a get_cache_key(request) method that returns the cache key for a given request, using the authenticated user's PK when available and falling back to IP; it must acquire a slot via ThrottleBackend keyed by scope and client ident on allow_request() and release it via finish_request(request); each slot entry must expire after a configurable slot_ttl (defaulting to 30 seconds) to prevent stale locks; both TokenBucketThrottle and ConcurrentRateThrottle must use self.timer() for all time calculations, allowing subclasses to override it for testing or custom time sources; Operation.run() and AsyncOperation.run() must invoke finish_request on every ConcurrentRateThrottle in their throttle_objects list inside a finally block after response processing or on error; UserConcurrentThrottle and AnonConcurrentThrottle convenience subclasses must mirror UserRateThrottle and AnonRateThrottle cache-key patterns; ConcurrentRateThrottle must default scope to "concurrent".
ThrottleBackend must be an abstract base class with get_state(key)/set_state(key, state, ttl)/delete_state(key) methods; CacheThrottleBackend must implement these using Django's default cache framework; all new throttle classes (TokenBucketThrottle, ConcurrentRateThrottle and their subclasses) must accept an optional backend parameter and use CacheThrottleBackend by default; ThrottleBackend, CacheThrottleBackend, and all convenience subclasses must be importable from ninja_extra.throttling.
throttle_request_allowed and throttle_request_denied signals (Django Signal instances) must fire from _check_throttles: throttle_request_allowed fires for each throttle that permits the request (sender=throttle.__class__, request=request, throttle=throttle), and throttle_request_denied fires for each throttle that denies it (same kwargs); the Throttled exception must expose a retry_after attribute as an integer (math.ceil of the wait value) or None when wait is None; both signals must be importable from ninja_extra.throttling.
