Title Model service lifecycle hooks for CRUD endpoints
Add model-service lifecycle hooks so that services expose sync hooks named before_create(context), after_create(context, instance), before_update(context), after_update(context, instance), before_patch(context), after_patch(context, instance), before_delete(context), after_delete(context, instance), plus async counterparts named before_create_async, after_create_async, before_update_async, after_update_async, before_patch_async, after_patch_async, before_delete_async, and after_delete_async with the same parameter conventions.
The context object must provide mutable .schema data for create, update, and patch flows, .instance for update, patch, and delete flows, and .kwargs containing route parameters; the instance parameter in after_delete must receive the deleted object with its identity fields (pk, id) preserved.
Each before_* hook must return a context object; if a before_* hook returns None instead, the endpoint must fall back to the original unmodified context as if the hook were a no-op. Each after_* hook (for create, update, and patch) must return an instance; if it returns None instead, the endpoint must fall back to the instance produced by the service or custom handler for response serialization. The after_delete and after_delete_async hooks are the exception: they must always return None to indicate the deleted instance is consumed and not serialized.
These hooks must wrap both auto-generated model routes and custom endpoints built with ModelEndpointFactory or ModelAsyncEndpointFactory so custom_handler execution observes the same lifecycle behavior and can be influenced by modified context values.
